1. 测试目标

验证 sm-crypto 的 HMAC-SM3 纯 JavaScript 实现在运行时是否通过时序侧信道泄漏密钥信息。

背景：2026 年 2 月，电子科技大学团队发表了 HMAC-SM3 功耗侧信道攻击（91.45% 密钥恢复成功率）。但该研究需要物理接触芯片进行功耗采集，且仅覆盖攻击维度。

本验证工作形成互补：纯 JS 环境下远程可测的时序 TVLA 验证，证明 sm-crypto 的 HMAC-SM3 实现不存在可远程利用的时序泄漏。

2. 测试方法

2.1 Fixed-vs-Random 协议

每组测试 Compare Group A（固定输入）与 Group B（随机输入），通过 Welch's t-test 判定两组时序分布是否存在统计显著差异：

  • Group A (Fixed)：每次迭代使用相同输入（固定密钥 + 固定消息）
  • Group B (Random)：每次迭代使用随机输入（随机密钥 / 随机消息）
  • 如果实现是时序恒定的，两组分布应无统计差异 → |t| < 4.5

  • 测试环境噪声水平可控（JIT 充分预热后时序稳定）
  • 无系统性测量偏差导致假阳性

4. 核心结论

✅ HMAC-SM3 8/8 全部通过 (N=2,000, max|t|=1.79 < 4.5)

sm-crypto 的 HMAC-SM3 纯 JavaScript 实现未检测到时序侧信道泄漏。3 项核心 HMAC-SM3 测试（消息保密性、全随机、密钥保密性）的 |t| 值均低于 1.8，远低于 4.5 阈值。


注：sm-crypto 的 HMAC-SM3 未做刻意恒定时间设计，实证结果说明其纯 JS 实现在 V8 引擎上天然不产生可检测的时序侧信道。这是 TVLA 方法论的核心价值——用实验数据验证安全假设，不依赖实现声明。
