# FIBEMATE 威胁模型 (Threat Model)

> 版本: 1.0 | 日期: 2026-06-08 | 适用于: FIBEMATE 开源发布

---

## 1. 信任边界 (Trust Boundary)

```
┌─────────────────────────────────────────────────────────────┐
│ 用户设备（浏览器）                                            │
│ ┌─────────────────────────────────────────────────────┐      │
│ │ 可信计算基（TCB）                    │  信任边界    │      │
│ │ ├─ 浏览器内存（私钥/共享密钥/明文）   │  ════════    │      │
│ │ ├─ ML-KEM-768 实现 (JS/WASM)        │     ║       │      │
│ │ ├─ 零知识证明生成器                  │     ║       │      │
│ │ └─ crypto.getRandomValues           │     ║       │      │
│ └─────────────────────────────────────┘     ║       │      │
│                                              ║       │      │
│ （密文 + ZK 证明）                           ║       │      │
└──────────────────────────────────────────────╬───────┘      │
                                               ║              │
                   ┌───────────────────────────╨───────────┐  │
                   │ 服务端（不在信任边界内）               │  │
                   │ ├─ 转发密文消息                      │  │
                   │ ├─ 验证零知识证明（不获知密码）        │  │
                   │ ├─ 管理会话元数据（在线状态/时间戳）    │  │
                   │ └─ 无法解密、无法获取私钥、无法冒充用户 │  │
                   └───────────────────────────────────────┘  │
```

### 边界断言

1. **私钥永不出浏览器** — 生成于 `crypto.getRandomValues`，仅存于内存，不被 `postMessage` 外传，不被序列化到 storage/localStorage
2. **服务端完全沦陷仍不影响机密性** — 无密钥存储，密文在黑盒中不可逆
3. **ZK 证明确保服务端验证时不获知密码** — 用户口令仅用于本地 ZK 证明生成，不以明文发送
4. **会话结束后 TCB 内无残留** — 无持久化密钥材料，页面关闭 → 密钥销毁

## 2. 资产清单 (Assets)

| 资产 | 存储位置 | 生命周期 | 敏感性 |
|------|----------|----------|--------|
| ML-KEM-768 私钥 | 浏览器内存 | 会话级 | **最高** — 泄露 → 所有消息可解密 |
| 共享密钥 (session key) | 浏览器内存 | 会话级 | **最高** — 泄露 → 当前会话消息可解密 |
| 明文消息 | 浏览器内存 DOM | 显示期间 | **高** — 泄露 → 单条消息暴露 |
| 用户口令 | 浏览器内存 | ZK 证明生成瞬间 | **高** — 泄露 → 可冒充用户 |
| 密文消息 | 服务端磁盘 / 内存 | 持久 / 会话 | **中** — 无密钥则无害 |
| ZK 证明 | 服务端（暂存验证） | 协议交互瞬间 | **低** — 零知识性质 |
| 会话元数据 | 服务端数据库 | 持久 | **低** — 谁在线、何时通信 |
| 公开密钥 | 服务端数据库 + 浏览器 | 持久 | **低** — 公钥是公开信息 |

## 3. 威胁建模矩阵

### 3.1 已缓解的威胁 (Mitigated)

| 威胁 | 攻击面 | 缓解措施 | 残留风险 |
|------|--------|----------|----------|
| **服务端入侵** | 服务器 OS / 应用层 | 端到端加密：服务端只存密文，无私钥 | 元数据泄露（在线状态、通信时间） |
| **数据库泄露** | DB dump / SQL 注入 | 无明文存储，无私钥字段 | 公钥 + 密文 + 元数据可被分析 |
| **中间人篡改密文** | 网络层 (TLS bypass) | ML-KEM-768 解密时隐式完整性校验失败 | 无（篡改密文 → 解密无效 → 拒绝） |
| **重放攻击** | 协议层 | 会话标识绑定 + 时间窗口 | 需确认实现中所有 API 端点包含 nonce |
| **服务端冒充** | 伪造公钥 / 证书 | ZK 证明 + 公钥固定 (certificate pinning) | 首次连接信任建立依赖 TLS |
| **被动监听** | 网络嗅探 / ISP | TLS 1.3 + E2EE 双层保护 | 仅 TLS 层可被国家级对手突破 |
| **时序侧信道** | 本地 JS 执行 | TVLA 测试通过（ML-KEM-768 实现已验证） | V8 引擎层不可控 |
| **内存转储** | 浏览器崩溃 / core dump | 无持久化密钥，会话级 | 运行时可被恶意扩展 dump |

### 3.2 已接受（合理风险下的残余威胁）

| 威胁 | 理由 | 缓解层次 |
|------|------|----------|
| **XSS 读取内存** | CSP + 沙箱降低概率，浏览器扩展权限超出控制 | CSP Header + Subresource Integrity |
| **浏览器 0-day** | 不在威胁模型范围内 | 建议用户保持浏览器更新 |
| **设备物理访问** | 完全属于用户责任域 | 屏幕锁 / 全盘加密 |
| **恶意浏览器扩展** | 扩展有能力读取所有页面 DOM | 用户需选择可信扩展，无法代码防御 |
| **V8 JIT 编译器侧信道** | 引擎级，JS 层不可控 | 已通过 TVLA 验证 JS 层无额外泄漏 |
| **元数据流量分析** | 加密不隐藏通信模式 | Mixnet 可缓解（阶段 2） |

### 3.3 明确不防御的威胁

| 威胁 | 原因 |
|------|------|
| **用户被胁迫交出设备** | 物理世界问题，非密码学可解决 |
| **用户主动泄露私钥/截图** | 社会工程 / 行为问题 |
| **量子计算机攻击当前会话** | ML-KEM-768 提供后量子安全；如被攻破则整个 NIST PQC 失效 |
| **浏览器厂商恶意后门** | 供应链问题，超出任何浏览器端应用能防御的范围 |

## 4. 威胁树 (Threat Trees)

### 4.1 攻击目标: 获取明文消息

```
获取明文消息
├── 攻击浏览器端 TCB
│   ├── XSS → 读内存 ← [CSP + SRI 缓解]
│   ├── 恶意扩展 → 读 DOM ← [不可防御]
│   ├── 浏览器 0-day → 任意代码 ← [不可防御]
│   └── 物理访问 → 内存 dump ← [不可防御，会话级]
│
├── 攻击服务端
│   ├── 入侵服务器 → 获取密文 ← [无害，无密钥]
│   ├── 数据库泄露 → 获取密文 ← [无害，无密钥]
│   └── 替换公钥 → MitM ← [ZK 证明缓解]
│
├── 攻击加密算法
│   ├── ML-KEM-768 密码分析 ← [NIST 标准] 
│   ├── 侧信道 → 提取密钥 ← [TVLA 已验证常量时间]
│   └── 随机数预测 ← [crypto.getRandomValues, CSPRNG]
│
└── 攻击网络层
    ├── TLS 降级/剥离 ← [HSTS + TLS 1.3]
    └── 流量关联分析 ← [Mixnet 可缓解 (阶段2)]
```

### 4.2 攻击目标: 冒充用户

```
冒充用户
├── 窃取私钥 → 见"获取明文消息"攻击树
├── 窃取口令
│   ├── 键盘记录 ← [OS 级，不可防御]
│   ├── 钓鱼页面 ← [用户责任]
│   └── 暴力破解 ZK 证明 ← [ZK 安全性 + rate-limit]
│
└── 绕过认证
    ├── JWT 重放 ← [短 TTL + 会话绑定]
    └── 会话固定 ← [每次握手新 nonce]
```

## 5. 安全属性对照表

| 属性 | 是否提供 | 说明 |
|------|----------|------|
| **机密性** (Confidentiality) | ✅ 端到端 | 服务端可见密文，不可解密 |
| **完整性** (Integrity) | ✅ 隐式 | ML-KEM-768 解密失败 = 篡改检测 |
| **认证性** (Authentication) | ✅ ZK | 零知识证明验证身份，密码不传输 |
| **前向安全** (Forward Secrecy) | ✅ 会话级 | 私钥不持久化，每会话重生成 |
| **后向安全** (Post-Compromise Security) | ⚠️ 部分 | 新会话 → 新密钥对；旧会话不可恢复 |
| **不可否认性** (Non-Repudiation) | ❌ 不提供 | 设计目标：可否认通信 |
| **匿名性** (Anonymity) | ⚠️ 部分 | 服务端无实名要求；Mixnet 阶段 2 增强 |
| **元数据保护** (Metadata Protection) | ❌ 不提供 | 当前版本服务端可见通信模式 |

## 6. 对用户的安全承诺

### 我们承诺：

> 如果 FIBEMATE 按文档部署、浏览器无恶意扩展、用户未主动泄露：
>
> 1. **服务端被完全入侵，历史消息仍不可解密**
> 2. **数据库被完整导出，不泄露任何明文或密钥**
> 3. **网络流量被全量捕获，攻击者看到的只有密文**
> 4. **后端管理员无法冒充任何用户发送消息**
> 5. **每次会话使用独立密钥对，历史会话不会因当前会话密钥泄露而回溯解密**

### 我们不承诺（明确声明）：

> - 防御浏览器 0-day 漏洞
> - 防御恶意浏览器扩展
> - 防御设备物理访问
> - 隐藏通信元数据（谁在何时与谁通信 — 阶段 2 Mixnet 改善）
> - 防御用户自身的社会工程风险

## 7. 验证方法

用户可以自行验证以上安全声明：

| 声明 | 验证方法 |
|------|----------|
| 私钥不离开浏览器 | 打开 DevTools → Network 面板，确认无 POST body 含私钥 |
| 服务端无私钥存储 | 检查服务端数据库 schema，无 `private_key` 字段 |
| 端到端加密 | 浏览器 console 抓取 `encaps()` 输出 → 对比 Network 面板 payload → 应只有 `ciphertext` |
| 常量时间实现 | 运行 `tvla_9of9_corrected.js`（含在仓库中） |
| 代码完整性 | 验证 DigiCert / 联合信任 TSA 时间戳（仓库内提供验证脚本） |
| 会话隔离 | 页面刷新 → Network 面板出现新 `encaps()` → 证明新密钥对已生成 |
| ZK 证明确保不传密码 | 抓取 `/auth` 请求 body → 应只含 `proof` 字段，无 `password` |
