# 混合密钥交换动态对比 — 可视化设计文档

**类型**：2D/3D 对比动画
**状态**：设计阶段（冻结期内不实现）
**优先级**：#1（最高）
**预计可视化耗时**：2-3 小时

---

## 1. 目标

直观对比「纯 ECDH」vs「纯 ML-KEM」vs「混合 ECDH + ML-KEM」三种密钥交换路径的安全边界和性能特征。让非密码学背景的观众一眼看出"为什么要混合"。

**核心叙事**：ECDH 快但量子不安全；ML-KEM 量子安全但更慢；混合 = 两者都要。

## 3. 视觉结构

### 3.1 三轨道布局

```
┌──────────────────────────────────────────────┐
│  [ECDH Only]  ─  [ML-KEM Only]  ─  [Hybrid]  │
│    轨道 A           轨道 B          轨道 C     │
├──────────────────────────────────────────────┤
│                                              │
│   每个轨道包含:                               │
│   - 顶部: 安全等级仪表盘                      │
│   - 中部: 协议流程动画（粒子流）               │
│   - 底部: 性能条形图                          │
│                                              │
└──────────────────────────────────────────────┘
```

### 3.2 轨道 A：纯 ECDH (P-256)

| 视觉元素 | 设计 |
|----------|------|
| 安全仪表 | 经典安全 🔵 / 量子安全 🔴（大红色叉号） |
| 流程动画 | Alice ↔ Bob 各生成密钥对 → 交换公钥（粒子流）→ HKDF 派生会话密钥 |
| 性能条 | 极快（绿色长条 ~1ms） |
| 公钥尺寸 | 65B（小盒子） |

### 3.3 轨道 B：纯 ML-KEM-768

| 视觉元素 | 设计 |
|----------|------|
| 安全仪表 | 经典安全 🟢 / 量子安全 🟢 |
| 流程动画 | Alice keygen() → 公钥发给 Bob → Bob encaps(pk)→ 密文回传 → Alice decaps(ct) → 共享秘密 |
| 性能条 | 中等（黄色条 ~2.5ms） |
| 公钥尺寸 | 1184B（大盒子，视觉对比 A 轨道的 65B） |

### 3.4 轨道 C：混合 (SM2 + ML-KEM-768)

| 视觉元素 | 设计 |
|----------|------|
| 安全仪表 | 经典安全 🟢 / 量子安全 🟢 / 冗余 🟢 |
| 流程动画 | 两个子轨道同时运行（ECDH + ML-KEM 并行），然后 HKDF(sm2_ss ‖ mlkem_ss) 合并 |
| 性能条 | 慢（橙色条 ~3.5ms），但标注"仅比 ML-KEM 多 ~1ms" |
| 公钥尺寸 | 65+1184=1249B |
| 连接线 | 从 A 和 B 各引一根线到 C，表示"继承两者优势" |

## 5. 技术栈（实现阶段参考）

- **画布**：Three.js（3D 粒子轨道）+ Canvas 2D（性能条/仪表盘）
- **数据**：从现有 `src/tls-hybrid-extension.js` 提取性能基准（已在 README 中记录：Path C-2 p95=78.5ms 含 SM2 ECDH）
- **自托管**：Three.js 从本地 `/lib/three.module.js` 加载（参照 LG 矩阵场经验）
- **无外部依赖**：不含 CDN，不含 npm 运行时包
