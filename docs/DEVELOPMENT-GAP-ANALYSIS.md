# FIBEMATE 开发流程与测试体系缺口分析 (Development Gap Analysis)

> 创建：2026-08-06（开源倒计时 D-25）
> 目的：记录 FIBEMATE 在"大厂级"开发流程和测试体系上的主要缺口，8/31 开源后对照执行，逐步补齐工程化体系。
> 状态：规划文档，不修改任何代码或发布配置。

## 优先级摘要

| 优先级 | 缺口 | 预计耗时 |
|:---:|------|:---:|
| **高** | 单元测试覆盖率测量（`nyc`/`c8`） | 2h |
| **高** | 补充 Prettier + CI 格式化检查 | 1h |
| **高** | 模糊测试 CI 集成（`jsfuzz`） | 4h |
| **中** | ADR 文档补充 | 2h |
| **中** | TypeScript 迁移起步 | 1-2 周 |
| **中** | 自动化 Release + CHANGELOG | 2h |
| **低** | 混沌测试 / DAST（ZAP） | 按需 |

## 3. 测试体系

| 层级 | 大厂实践 | FIBEMATE 当前状态 | 补充方案 |

## 执行原则

- **冻结期（8/31 前）**：本文档仅作规划，不触发任何代码/CI 变更。
- **开源后优先级**：先补齐"高"优先级三项（覆盖率测量、Prettier、模糊测试），它们直接提升代码可信度且改动可控。
- **渐进迁移**：TypeScript / SonarQube 等重资产项按"中"优先级排期，避免一次性大重构冲击已验证代码。
- **安全优先**：第三方审计与威胁建模按路线图（Q4 2026）推进，不阻塞开源。
