# 纵深防御架构设计：WASM 混淆 + NIST PQC

> **状态**：技术预研 · 归档于 2026-08-07  
> **适用范围**：8/31 开源后工程化参考，不在开源前冻结期开发  
> **不包含**：VWZ（已战略剔除，不入生产链路）

---

## 目标

构建面向 Wasm 客户端的纵深防御体系，分层递进，一层失守，其余层继续生效；客户端只做防护，**信任根完全放在服务端**。

---

## 五层架构（由外到内）

```
【攻击者】
  ↓
① 外层：Wasm 虚拟化壳 + 控制流混淆（O-MVLL / Crystalline）
    抵御：静态反编译，普通人工逆向
    弱点：无法抵御动态调试、内存 dump、e-graph 代数化简
  ↓
② 中间层：LookingGlass v2.2（仅对高价值数值计算函数开启）
    抵御：代数化简、符号执行、静态 AI 扒取常量与运算逻辑
    弱点：内存 dump 拿到运行时群参数则整层失效；不保护控制流
  ↓
③ 运行时防护：调试检测 + 内存完整性 L8/L9 + 断点检测
    目的：提高对手 dump 内存的门槛，保护 LG 运行时参数
    弱点：浏览器 Wasm 环境无硬件级保护，无法 100% 阻止专业 dump
  ↓
④ 密码协议层：ML-KEM-768（密钥封装）+ SLH-DSA（签名验签）
    标准 NIST PQC，不引入自定义假设密码
  ↓
【网络传输】
  ↓
⑤ 服务端兜底：验签 + 业务二次校验 + 风控告警（信任根）
```

---

## 各层详细说明

### 第 1 层：外层静态对抗

**组件**：Wasm 虚拟机壳 + 控制流混淆（O-MVLL / Crystalline）

| 能力 | 说明 |
|:---|:---|
| 控制流扁平化 | 抹除原始 Wasm 指令流 |
| 伪造基本块 | 增加逆向干扰 |
| 指令虚拟化膨胀 | 提高反编译成本 |

**对抗对象**：静态反编译工具、普通人工静态逆向  
**固有弱点**：无法抵御动态调试、内存 dump；不能抵御代数化简攻击

### 第 2 层：中间层数据流对抗

**组件**：LookingGlass v2.2（**仅对核心数值计算函数开启**）

| 能力 | 说明 |
|:---|:---|
| 有限群代数变换 | 破坏常量、中间运算 |
| 七层不等价群表示 | e-graph/SMT 符号执行失效 |
| 局部开启 | 只保护高价值计算，降低性能损耗 |

**对抗对象**：自动化代数化简、批量 AI 逆向、脚本小子  
**关键原则**：不对全模块混淆；只选核心算法、校验逻辑开启

⚠️ **依赖第 3 层的反调试/反 dump 能力保护本层的运行时参数**

### 第 3 层：运行时防护层

**组件**：内存完整性校验 + 断点检测 + 调试器探测 + L8/L9 运行时自检

| 能力 | 说明 |
|:---|:---|
| 篡改检测 | 检测简单 patch 篡改 |
| 调试器附加检测 | 识别调试器状态 |
| 秩异常检测（L8/L9）| 检测 LookingGlass 混淆层被破坏 |

**局限**：浏览器 Wasm 环境没有硬件级保护，无法 100% 阻止专业 dump，只能抬高攻击成本  
**作用**：这一层是第 2 层的保护层——不让攻击者轻易拿到 LG 的会话矩阵

### 第 4 层：密码协议层

**组件**：NIST 标准后量子密码

| 算法 | 用途 | 说明 |
|:---|:---|:---|
| ML-KEM-768 | 密钥封装 | 客户端-服务端后量子安全密钥协商 |
| SLH-DSA | 数字签名 | 服务端持有私钥下发签名，客户端上报结果后验签 |

❗ **不使用 VWZ 作为生产密码；VWZ 仅用于实验室多假设冗余研究**

### 第 5 层：服务端兜底

> 这是整个体系真正的最后防线。客户端所有防护全部可以被攻破，**永远不信任客户端输出**。

| 能力 | 说明 |
|:---|:---|
| 验签 | 校验 SLH-DSA 签名合法性 |
| 业务二次校验 | 输入范围校验、频率风控、行为异常检测、重放防护 |
| 风控告警 | 识别异常请求，拦截批量破解行为 |

## 攻击路径与各层阻力

| 攻击者类型 | 攻击手法 | 阻力来源 |
|:---|:---|:---|
| 脚本小子 / AI 静态逆向 | 跑 SMT/e-graph 工具 | ① 外层 VM 壳提高解析难度；② LG 直接废掉代数化简 |
| 中级逆向，人工动态调试 | 附加调试器、尝试 patch | ③ 运行时检测触发异常；绕过 L8 后还需手工剥离 LG 群变换 + 逆向 VM 字节码 |
| 高级攻击者，完成内存 dump | 绕过调试检测，dump 进程内存 | ①②③ 全部失守；但 ④ 密码层 + ⑤ 服务端兜底仍然有效——上报数据依然要经过验签和业务校验 |

**关键点**：第 1-4 层全部失守，第 5 层依然可以守住业务安全——这才算合格的纵深防御。

---

## 性能与工程取舍

1. **LG 不要全局开启**——只对少量高价值计算函数做局部混淆，降低 Wasm 性能损耗与二进制膨胀
2. **虚拟化壳本身有性能开销**——二者叠加必须做完整性能测试；高频循环函数谨慎开启 LG
3. **不要产生"绝对安全"的幻觉**——浏览器 Wasm 环境不存在真正的防 dump，只能增加成本，做不到绝对阻止
4. **密码组件严格使用 NIST 标准化算法**——不引入自定义假设密码

---

## 已知风险清单

| 风险 | 严重程度 | 说明 |
|:---|:---:|:---|
| Wasm 引擎兼容性 | 中 | LG + 虚拟化壳叠加可能触发未定义行为，必须完整回归测试 |
| 反调试检测被绕过 | 中 | 不能当做安全硬边界 |
| 混淆被击穿 | 低（可接受）| 客户端只是成本增加层，业务安全由服务端兜底 |
| 业务安全寄托于客户端混淆 | 高（禁止）| 永远不信任客户端 Wasm 输出 |

## 纵向依赖关系

```
第 5 层（服务端）  ──────────────────────  信任根，永远有效
                                            ↑
第 4 层（密码层）  ──────────────────────  标准算法，信任根辅助
                                            ↑
第 3 层（运行时）  ──┐
                    │  保护第 2 层不被轻易击穿
第 2 层（LG v2）  ──┘  （若无第 3 层，dump 可直接破第 2 层）
                    │
第 1 层（VM 壳）  ──────────────────────  基础屏障
```

⚠️ **缺少第 3 层（反 dump）时，LG 第 2 层容易被一次性击穿，纵深链条直接断裂。
