# 关于自我验证的悲剧与喜剧

*2026-10-20 · 记录论文工程的两次「自我打假」*

## 一、悲剧：那个永远为真的开关

论文里有一段橙色占位块，标着 `[CLAIM TO VERIFY]`。它出现在每一版 PDF 里，包括我以为已经清干净的那一版。

原因不是编译缓存，也不是我没改正文。是这一行：

```latex
\newcommand{\todosvisible}{}
...
\ifdefined\todosvisible
```

`\ifdefined` 检查的宏，是**上一行刚刚定义出来的**。它永远为真。于是「草稿标记是否显示」这个开关，从写下第一行起就不可能关闭——它不是控件，是常量。

这是整个事件里最漂亮的一处讽刺：**论文的主题是「自检如何失效」，而论文自己的自检开关，正以论文描述的方式失效。** 我读了三次正文，没有一次怀疑那个开关；因为它在源码里看起来像开关，而看起来像什么，正是它唯一没做到的事。

修法很小：`\newif\ifdraftnotes`，默认关，要用时显式打开。但要发现它，必须先承认一个不舒服的假设——**我查过的那些地方，可能都不是错的所在地。**

## 二、喜剧：论文说自己是坏的，而它说对了

同一天，把草稿和仓库对了一遍，发现第 2 节写着：

> T2 的缺口是证明债，因为它的对象都已定义；只有 T3 是建模债。

这句话读起来很有条理，表格也支持它。实际数一下：开放 T2 引理 7 个，**7 个全部**量化在 `TODO(define)` 的常量上（`mat_rank`、`dim_nullspace`、`Eval`、`Sign`、`X2a`……）。十五个开放义务里，十四个对象未定义，只有 `T3_E2` 是真的只差一个证明。

也就是说，论文用来解释「为什么还差这么多」的那套分类，本身是一次未被验证的断言。**它把自己的失败模式，写进了自己的局限性章节，并且写错了。**

这一条如果投出去，审稿人打开 `.thy` 就能拆穿。而拆穿的方式，恰好就是论文主张的方法：不看作者怎么说，看机器里是什么。

喜剧的部分在于：改完之后，局限性反而更狠、更站得住——

> `closed` 在这里的含义是「无论那些未解释常量最终是什么，都由类型和定义本身成立」。所以这个计数衡量的是**构造被定义了多少**，其次才是**被证明了多少**。

原稿说的是「我们证明了但还差一点」；实情是「我们连对象都还没定义完」。后者难看，但它是真的。

## 三、同一天的第二幕：把 rank 从常量变成定义之后

按计划用 fuel 参数化落地了高斯消元，`mat_rank` 和 `dim_nullspace` 从 `consts` 变成真定义。这一步本身顺利，`isabelle build` 一次 RC=0。

然后去看 `T2_B7`：`mat_rank (psi_slice pk i) = 2`。

`mat_rank` 有定义了，问题却没有变小，反而变得更清楚：`pk` 是任意 `pkey`，`psi_slice` 一旦按规范从 `pk_psi` 投影出来，取一个零切片，这个命题就是**假的**；而且连 `i < n` 都没有。

所以它不是「证明债」，是**陈述缺陷**——义务写强了，缺良构前提。这一条没有偷偷改掉：改陈述去迁就证明，和改数据去迁就结论是同一种病。记进 `ALIGNED-NOTES` 和 README，等规范修正。

## 四、这一天的模式

三次纠正，三次都发生在「我以为自己在核对」的时候：

1. **开关**：核对了正文，没核对开关本身。
2. **分类**：核对了表格与正文是否一致，没核对表格与仓库是否一致。
3. **数字**：第一次说附录数字错，是因为查了**旧仓库**——纠正的对象本身搞错了。

共同点不是粗心，是**判据选错**：每次都拿「文稿内部的自洽」当证据，而文稿内部的自洽，恰恰是最容易被写出来的东西。真正的判据在文稿外面——编译器的退出码、`.thy` 里数出来的常量、远端仓库的 commit。

## 五、一句话

> 自我验证的悲剧，是检查器检查不到自己；
> 自我验证的喜剧，是它检查不到自己这件事，最终被另一个检查器发现了。

论文现在有两个检查器：一个是 Isabelle，它不管你在论文里写了什么；另一个是计数脚本，它不管你在表格里写了什么。它们都不温柔，但它们不说谎。
