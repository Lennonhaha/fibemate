## Why the third case is the load-bearing one

An unknown sha only proves that a missing object is missing. The third case uses a commit
that exists in the repository and whose content is valid — only the commit production
serves differs. A checker that reports success there would be measuring the repository,
not the deployment.

## When to re-run

After changing `deploy-evidence.cjs`, `check-deploy-alignment.cjs`, `runtime-paths.cjs`,
or the `--tree` arguments of `deploy-release.sh`. The first case fails if the path set and
the deploy script disagree, which is the one divergence neither of them can notice alone.
