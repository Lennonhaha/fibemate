## 一则新闻，和我的一个问题

2024 年，NIST 正式发布了后量子密码学标准：ML-KEM（原 Kyber）、ML-DSA（原 Dilithium）、SLH-DSA（原 SPHINCS+）。这意味着后量子时代正式开启。

然后呢？

大多数工程师面临的问题是：标准文档看完了，数学公式推导也懂了，但怎么把它变成可运行的代码？现有库要么太重（liboqs），要么缺文档，要么没有可视化。理论和工程之间，隔着一道很深的沟。

这就是 FIBEMATE 试图回答的问题。

---

## FIBEMATE 是什么

**FIBEMATE** 是一个全栈后量子密码工程验证平台——不是生产级密码库，是一份透明的工程记录。

两年时间，一个人，从数学公式出发，一路做到 Web 可视化和 FPGA 比特流。

项目全部代码在 GitHub 开源（GPL-3.0-only），全部声明都有可运行的测试和第三方时间戳存证，没有保留。

## 我实现了什么

### 密码学算法（覆盖 NIST + 国密两条线）

| 算法 | 标准 | 说明 |
|:---|:---|:---|
| **ML-KEM-768** | FIPS 203 | 完整 NTT 实现，10,000 组 KAT 向量验证 |
| **ML-DSA-65** | FIPS 204 | 参考实现，与 noble/post-quantum 字节级对齐 |
| **SLH-DSA-128s** | FIPS 205 | 无状态基于哈希的签名 |
| **SM2** | GB/T 32918 | 国密椭圆曲线，含侧信道安全实现 |
| **SM3** | GB/T 32907 | 国密哈希函数 |
| **SM4** | GB/T 32907 | 国密分组密码，含 GCM 模式 |

### 协议与集成

- **TLS 1.3 混合 KEM**：X25519 + ML-KEM768 混合握手，完整实现，附 10 步 3D 可视化
- **双棘轮协议**：后量子增强 Signal 协议，含 TLA+ 形式化验证模型
- **Hybrid KEM**：经典 + 后量子密钥封装混合方案

### 硬件实现

- **FPGA Verilog RTL**：Artix-7 上的 NTT 协处理器，含 BRAM 仿真
- **硬件侧信道验证**：TVLA（Test Vector Leakage Assessment）框架，遮掩实现验证通过

### 26 个交互式可视化

这是 FIBEMATE 最有意思的部分——每一个算法、每一个协议步骤，都有在线可运行的 3D 可视化页面：

- 3D 密钥生成流程（ML-KEM / ML-DSA / SM2）
- LWE 攻击难度地形图（维度 × 模数 × 攻击成本）
- TVLA 侧信道测试仪表盘（修复前 → 修复后对比）
- TLS 1.3 混合握手 10 步序列图
- 格密码安全等级对比（lattice-estimator 真实数据）
- FPGA 资源热力图
- 协议层次结构全景图

全部在 fibemate.net 上可直接访问，不需要安装任何东西。

## 100 份时间戳存证

这是 FIBEMATE 区别于大多数开源项目的地方：每一项声明都有对应的可运行测试，加上 DigiCert / FreeTSA 双机构时间戳存证。

你想验证 ML-KEM-768 的 TVLA 数据？直接跑测试脚本。你想验证某个算法的 KAT 向量？直接对比。你想验证某个声明的时间？存证链可查。

这不是营销材料，是可审计的工程证据。

## 诚实地说明局限性

这不是一份完美的宣传稿。有几件事必须说清楚：

**ML-KEM-768 是纯 JavaScript 实现**
这是为了可读性和教育目的，不是为了极致性能。和 OpenSSL 比会慢 100-1000 倍，这是语言差距，不是实现质量问题。

**SM2 验证的侧信道安全**
遮掩实现（masked implementation）TVLA 测试通过，但纯 JavaScript 的 verify 函数并非常数时间。如果你需要侧信道安全的 SM2，WASM 重写（Phase 1）正在路线图上。

**硬件侧信道测试**
完整的 ChipWhisperer 物理测试还未做，现有结果基于仿真。FPGA 上的真实侧信道测试需要硬件设备。

**LookingGlass 协议**
形式化验证完成（TLA+），但尚未作为标准协议部署。数学上是安全的，工程部署是另一回事。

所有这些，都在文档里有明确说明。没有"高性能""生产级""企业用"这样的词。

## 为什么做这个

说到底，这是一件很个人的事。

我花两年时间把后量子密码学从数学公式变成可运行的代码，不是因为 liboqs 不够好，而是因为自己动手做一遍，才是真正理解它的唯一方法。

NTT 怎么分解素域多项式？ML-KEM 的解密失败率怎么算？BKZ 算法需要多大块才能破 LWE？这些问题看标准文档能看懂，但自己写出来跑一遍，才知道坑在哪里。

**开源不为别的，只为让这个过程有记录、可审计、能为其他人所用。**
