# FIBEMATE 产品路线图（8/31 开源后衍生方向）

> **用途**：8/31 开源后的产品化演进依据。冻结期（8/31 前）不触发任何动作，不触碰主分支代码。
> **定位声明**：FIBEMATE 当前是后量子密码学全栈工程验证平台（PQC executable textbook，GPLv3）。以下为开源后**可能的衍生方向**，是规划而非当前承诺。
> **配套文档**：[`DEVELOPMENT-GAP-ANALYSIS.md`](DEVELOPMENT-GAP-ANALYSIS.md)（工程缺口）、[`NIST-CSF-GAP-ANALYSIS.md`](NIST-CSF-GAP-ANALYSIS.md)（框架合规差距）、[`CALL-FOR-COLLABORATORS.md`](CALL-FOR-COLLABORATORS.md)（招募降 Bus Factor）。

## 一、概述

三大衍生方向基于现有资产复用率排序：

| 方向 | 资产复用率 | 一句话定位 |
|------|:---:|-----------|
| 企业级 PQC 迁移工具 | ⭐⭐⭐⭐⭐ | 把验证能力产品化，帮企业发现量子脆弱资产 |
| 底层基础设施（硬件 IP + SDK） | ⭐⭐⭐⭐ | 把验证成熟的算法模块以可授权形式输出 |

## 二、方向一：企业级 PQC 迁移工具

### 产品定位
PQC 迁移就绪平台——帮助企业自动发现量子脆弱资产、评估迁移紧迫性、输出合规报告。

### 核心资产复用
| 现有资产 | 产品化模块 |
|----------|-----------|
| PQC 部署验证器（`pqc-deployment-checker.html`）| 端点扫描器：批量扫描企业 TLS 端点，检测 PQC 就绪度 |
| CBOM 资产审计（`cbom-cyclonedx.json`）| 资产发现引擎：自动生成企业加密资产清单 |
| PQRA 自评（52 题）| 就绪度评估工具：生成七维雷达图和差距报告 |
| 量子迁移优先级矩阵（Europol 模型）| 迁移路线图生成器：自动输出 P0/P1/P2 优先级 |
| NIST CSF 2.0 差距分析 | 合规报告生成器：一键生成 NIST / ISO / CNSA 2.0 报告 |

### 产品形态
| 形态 | 说明 | 定价模式 |
|------|------|---------|
| 开源社区版 | 单次扫描、手动输入 | 免费 |
| 企业 SaaS 版 | 批量扫描、自动报告、持续监控 | 订阅制（按端点 / 月）|
| 私有化部署版 | 企业内网部署，数据不出本地 | 年费授权 |

### 开发优先级（3–6 个月）
1. 部署验证器 CLI → 批量扫描引擎（2 周）
2. PQRA + NIST CSF 整合为合规报告（2 周）
3. 历史趋势看板 + 持续监控（2 周）
4. SaaS 后端 + 用户管理（4 周）

### 市场对标
| 竞品 | 模式 | 定价 |
|------|------|------|
| SafeLogic SafePQ | 合规咨询 + 软件授权 | 定制报价 |
| QSE QPA v2 | 企业迁移评估工具 | 定制报价 |
| liboqs 集成咨询 | 开源 + 商业支持 | 按小时 |

## 三、方向二：底层基础设施（硬件 IP + 中间件）

### 产品定位
PQC 安全硬件 IP 核 + 跨平台 SDK——将已验证的算法模块以可授权形式输出，供芯片设计厂商和嵌入式开发者集成。

### 核心资产复用
| 现有资产 | 产品化模块 |
|----------|-----------|
| FPGA NTT 加速器（`rtl/`）| NTT 硬件 IP：Verilog 核心，Artix-7 已验证，WNS 9.755ns |
| ML-KEM-768 实现（C + WASM + JS）| PQC 跨平台 SDK：统一的 C/WASM/JS API |
| SM2/SM3/SM4 国密实现 | 国密合规套件：供政府 / 金融客户使用 |

### 产品形态
| 产品 | 说明 | 定价模式 |
|------|------|---------|
| NTT 硬件 IP 核 | Verilog 源码 + 测试套件 + 文档 | 一次性授权 + 版税 |
| PQC SDK（C/WASM/JS）| 编译好的库 + API 文档 | 开源（AGPL）或商业授权（MIT）|
| 国密合规套件 | SM2/3/4 实现 + 国密证书 | 定制报价 |

### 开发优先级（6–12 个月）
1. 封装 NTT IP 为可交付包（源码 + 测试 + 文档）（4 周）
2. 补充 SM2 WASM 恒定时间实现（Phase 1）（4 周）
3. 发布跨平台 SDK（npm / PyPI / crates.io）（4 周）
4. 国密合规认证申请（按需，外部流程）

### 市场对标
| 竞品 | 模式 | 定价 |
|------|------|------|
| GlobalPlatform Pavona | 开源硅平台（TSMC 3nm）| 开源 + 商业支持 |
| Rambus PQC IP | 硬件 IP 授权 | 定制报价 |
| liboqs 集成服务 | 开源 + 商业支持 | 按小时 |

## 四、方向三：垂直场景组件

### 产品定位
PQC 安全通信组件——将 FIBEMATE 的协议层模块包装成可嵌入的 SDK，供区块链、物联网、隐私通信等垂直场景使用。

### 核心资产复用
| 现有资产 | 产品化模块 |
|----------|-----------|
| Double Ratchet 协议（`double-ratchet-pq.js`）| PQC 安全通信 SDK：端到端加密通信组件 |
| X3DH + OPK 预密钥协议 | 异步安全消息组件：离线消息队列场景 |
| 零知识证明（Bulletproofs）| 匿名认证组件：隐私保护登录 / 交易 |
| Sphinx 包格式 + Mixnet | 元数据隐私保护层：洋葱路由通信 |

### 产品形态
| 产品 | 说明 | 定价模式 |
|------|------|---------|
| 安全通信 SDK | 供即时通讯 / 协作工具集成的 PQC E2EE 组件 | 年费授权 |
| 匿名认证组件 | 供区块链 / DeFi 集成的零知识登录方案 | 按交易收费 |
| PQC 中间件 | 供企业应用快速集成 PQC 加密能力 | 定制报价 |

### 开发优先级（6–12 个月）
1. 梳理现有协议模块，设计统一 SDK API（2 周）
2. 封装 Double Ratchet + X3DH 为独立 npm 包（2 周）
3. 封装 ZK 认证模块（2 周）
4. 编写集成文档 + 示例代码（2 周）

### 市场对标
| 竞品 | 模式 | 定价 |
|------|------|------|
| Signal Protocol | 开源（AGPL）| 免费 |
| Matrix Olm/Megolm | 开源（Apache）| 免费 |
| Wire 加密组件 | 开源（GPL）+ 商业支持 | 定制报价 |

## 五、对比与建议

| 方向 | 资产复用率 | 开发周期 | 市场成熟度 | 定价空间 | 适合阶段 |
|------|:---:|------|:---:|:---:|---------|
| 企业级迁移工具 | ⭐⭐⭐⭐⭐ | 3–6 个月 | 高（需求明确）| 高 | 立即启动 |
| 硬件 IP + SDK | ⭐⭐⭐⭐ | 6–12 个月 | 中（增长期）| 高 | 8/31 后 3 个月启动 |
| 垂直场景组件 | ⭐⭐⭐ | 6–12 个月 | 中 | 中 | 8/31 后 6 个月启动 |

**优先级判断**：
1. **企业级迁移工具**——资产复用率最高（已有 ~80% 模块），市场明确，3–6 个月可产品化
2. **硬件 IP + SDK**——技术壁垒最高，差异化最强，但周期较长
3. **垂直场景组件**——依赖市场成熟度，可做长期布局
