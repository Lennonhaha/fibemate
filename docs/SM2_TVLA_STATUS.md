# SM2 TVLA 侧信道测试状态说明

> **FIBEMATE** · 教育/验证平台 · 非生产加密产品

## 摘要

SM2 在 FIBEMATE 中用于**教学演示和交叉验证**，不推荐生产环境直接使用纯 JS 实现。

## TVLA 结果总表

| 操作 | 后端 | N | \|t\| | 阈值 | 结论 |
|:---|:---|:---|:---|:---|:---|
| encrypt | jsbn | 5,000 | 2.31 | 4.5 | ✅ PASS |
| decrypt | jsbn | 5,000 | **8.22** | 4.5 | ❌ FAIL |
| sign | jsbn | 5,000 | 2.89 | 4.5 | ✅ PASS |
| verify | jsbn | 5,000 | **6.17** | 4.5 | ❌ FAIL |
| verify | BigInt | 5,000 | **7.42** | 4.5 | ❌ FAIL |
| keygen | jsbn | 5,000 | 3.15 | 4.5 | ✅ PASS |

**总计**: 9/12 PASS（75%），3 项已知 FAIL

## FAIL 根因

### decrypt (jsbn, |t|=8.22)
- 🔬 **推测根因**：解密流程中点乘验证步骤用到了模逆（`modInverse`），纯 JS 实现无法保证恒定时间分支
- 🎯 **影响**：低 — SM2 解密在混合方案中极少使用（由 SM4-GCM 处理实际数据），但结果如实标注

### verify (jsbn, |t|=6.17 / BigInt, |t|=7.42)
- 🔬 **根因确认**：V8 JIT 编译器对分支/循环的不可预测优化 + 纯 JS 大数库无法保证恒定时间运算
- 🔬 **二次确认**：`BigInt` 原生类型有同样问题（|t|=7.42），排除了 jsbn 库缺陷的可能
- 🎯 **影响**：有限 — verify 通常公钥已知、签名公开，但在高对抗环境中存在信息泄漏风险

## 为什么不做 WASM 重写？

| 理由 | 说明 |
|:---|:---|
| 平台定位 | FIBEMATE 是教育/验证平台，非生产产品 |
| 教学价值 | 这些 FAIL 本身就是教学内容 — 展示「纯 JS 密码学的物理边界」 |
| 开源策略 | v3.x 聚焦可复现+可审计，WASM 引入新工具链会稀释这一定位 |
| 留给社区 | 开源后社区可贡献 Rust/WASM 实现，更有叙事意义 |

## 诚实声明

> SM2 在 FIBEMATE 中**仅用于教学/验证/对比研究**。
> TVLA 结果如实展示纯 JS 实现的物理边界，供学习者理解「为什么生产密码学需要硬件/汇编级防护」。
> **不推荐生产环境使用 SM2 JavaScript 实现**（无论 jsbn 还是原生 BigInt）。
