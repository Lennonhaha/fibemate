# 官网版本不一致事故复盘

**日期**: 2026-08-12 | **严重程度**: 中（线上可见但未造成功能故障）

---

## 一、问题描述

官网 `fibemate.net` 首页 (`index.html`) 长期展示 **2026-07-21 旧版**：
- 标题: `v3.3-preview`、"隐私通信"定位
- TSR 计数: 91 份（实际已达 130+）
- 缺少 8 月份新增的所有可视化卡片（NTT 蝶形运算、PQC 仪表盘、格拓扑、挂谷集合、CARS 等 26 个工具）

而本地 workspace & GitHub `main` 分支早已更新为 `v3.3.0`、"PQC 工程验证平台"、完整可视化栏目。

---

## 二、根因

**服务器 git 工作目录停在 `experimental/vwz-lg` 分支，而非 `main`。**

nginx 的 `root` 指向 `/opt/fibemate-repo/www/`，该目录直接对应 git 工作树。当工作树在 `experimental/vwz-lg` 分支时，nginx 就服务该分支的旧版文件。

| 要素 | 旧版（线上） | 新版（main） |
|------|-------------|-------------|
| 分支 | `experimental/vwz-lg` | `main` |
| 版本号 | `v3.3-preview` | `v3.3.0` |
| 定位 | "隐私通信" | "PQC 工程验证平台" |
| 可视化工具数 | 少量 | 27 个 |
| TSR 数 | 91 | 130+ |

### 为什么会停在 `experimental/vwz-lg`？

推测时间线：
1. **8月12日 05:11** — 启动 LookingGlass v3 实验，切到 `experimental/vwz-lg` 分支进行 `lg-v3/`、`services/`、`attack/` 等文件开发
2. **期间** — 所有文件操作（commit、push）都在该分支上完成，未切回 `main`
3. **中间某次** — `main` 分支的 `www/index.html` 通过 git push 到了 GitHub，但服务器工作树仍在 `experimental/vwz-lg`，nginx 持续服务旧文件
4. **未被发现** — 后续所有操作（ESLint 修复、ROADMAP/ARCHITECTURE 创建、Dependabot 清理）都在本地 workspace → push GitHub 的路径上，没有触发"检查线上实际版本"的步骤

---

## 三、发现过程

- **08-11 晚间**：用户在浏览器中看到旧版页面（"隐私技术栈"、91 TSR），与本地/GitHub 上的新版不符，提出质疑
- **08-12 06:52**：排查发现服务器 `git branch` 输出 `experimental/vwz-lg`
- **08-12 06:55**：切回 `main`，`cp www/index.html` 重新部署（发现是同一文件——说明旧版是分支差异而非文件损坏）
- **08-12 07:04**：插入 tensor-field 卡片（26→27）+ commit `6e7e569f` → push

**从版本不一致产生（约8/12 05:11）到发现（约8/12 06:52），持续约 1 小时 40 分钟。** 但如果旧版在此之前就已经在线上（可能性更高——`experimental/vwz-lg` 分支的 index.html 就是 7/21 旧版），这个窗口可能长达 **2-3 天**。

---

## 四、为什么没有更早发现

| 原因 | 说明 |
|------|------|
| **无线上版本检查步骤** | 所有检查（git status、commit push、CI、测试）都在"代码是否正确"层面，没有"线上实际渲染版本"的验证环节 |
| **git push ≠ 线上更新** | push 到 GitHub 不等于 nginx 服务的文件更新——服务器工作树需要单独 `git checkout main && git pull` |
| **多分支切换遗留** | 实验分支 `experimental/vwz-lg` 切过去开发后未切回，无人察觉 |
| **nginx 无版本标头** | 响应未携带 git commit SHA 或版本号，无法从 HTTP 响应判断线上版本 |
| **浏览器缓存干扰** | 用户多次提到"手机还能访问"，旧版可能被 Service Worker 或浏览器缓存 |

---

## 五、改进措施（建议）

1. **部署后自检脚本** — push 后自动 curl 首页，grep 版本号/commit SHA 对比预期值
2. **nginx 添加版本标头** — `add_header X-Git-SHA <commit>` 或 `add_header X-App-Version v3.3.0`
3. **分支纪律** — 实验分支开发完成后立即切回 `main`；或在 nginx root 使用 `git archive` 静态导出而非工作树
4. **D-20 检查清单增加** — "线上 https://fibemate.net/ 版本号是否与当前 HEAD 一致"
5. **cron 自动巡检** — 每天一次 curl 对比预期版本，不一致时告警
