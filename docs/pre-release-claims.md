# FIBEMATE 发布前声明核对清单（PRE-RELEASE-CLAIMS）

> 版本：v1.1 · 日期：2026-10-14 · 适用：发布 / 官网更新 / 大型 PR 之前
> 目的：凡是**对外说过的话**，先要有出处。填不出可点击证据的声明，只有三条路：补证据、改措辞、撤回。
> 由来：多次出现「文案与实现不符」（见第四节）。口头约定拦不住，CI 目前只能拦其中一类。

---

## 一、怎么用

1. 复制下面**用得到的**小节（不必全填）。
2. 「证据」列写成**可点击来源**：`路径:行号`、commit sha、或 URL。
3. 填不出证据 ⇒ 该条**不许发布**。
4. 发布前再跑一遍第三节的机械核 —— 能自动拦的只有那几条，别指望它兜底。

### 2.5 已知限制（必须保留，不得删）

- 未经第三方独立审计，不应用于生产通信。
- 移动端身份密钥存于未加密的 AsyncStorage（非硬件后端）。
- 桌面端密钥保护依赖 Windows DPAPI（Windows-only，无 Keychain 等价物）。
- 研究线（VWZ、mixnet 等）代码不与主线合并，也不得作为产品能力宣传。

## 三、机械核（能自动拦的部分）

**R1 混写「CII / BP」** —— **已接入 CI**（`ci.yml` 的 `claim-check` job，实现在 `scripts/check-claims.cjs`）：

```bash
node scripts/check-claims.cjs
```

范围：`www/` 与 `README.md`；**排除 `www/docs/tsa/**`**（冻结存档，改动会破坏存证链）。
2026-10-14 首次运行时命中 1 处真阳性（`www/index.html`），已随该 PR 修掉。

**R2 绝对化词（窄表）** —— 须**人工判**，多数命中是「反绝对化」的诚实文案：

```bash
grep -rnE "牢不可破|零风险|无懈可击|绝对安全" www/ README.md docs/
```

**R3 版本号对齐** —— 与 `package.json` 比对，需白名单：

```bash
grep -rn "v3\.[0-9]\.[0-9]" www/index.html
```

**R4 自研叙事** —— **只可人工核**，现有命中几乎都是诚实标注，机械拦会误杀：

```bash
grep -rn "自研" www/ README.md
```

> 结论：R1 可直接进 CI；R2 与 R4 会误杀诚实文案，只做人工复核；R3 需白名单。
> 提醒：**本文件按定义会命中 R2 与 R4 的正则**（它引用了那些词做示例），复核时请连同本文件一起判。
