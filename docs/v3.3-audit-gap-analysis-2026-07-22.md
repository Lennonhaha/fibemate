# FIBEMATE v3.3 对标分析：同类开源 PQC 混合密码平台差距盘点

> 版本: v1.0 | 日期: 2026-07-22 | 作者: 用户独立审计
> 关联文档: docs/security-limitations.md, docs/testing.md, RELEASE.md

## 对标参照梯队

1. **底层密码库**：liboqs / oqs-provider、noble-post-quantum
2. **混合通信原型**：oqs-demos、OpenSSL PQC 分支、Cloudflare post-quantum-tls
3. **全栈工程平台**（密码+服务+前端+硬件原型）：极少同类项目
4. **国内国密+PQC 混合赛道**：几乎无公开完整竞品

---

## 一、FIBEMATE 独有差异化优势

| # | 优势 | 竞品对比 |
|---|------|----------|
| 1 | SM2 + ML-KEM-768 混合 KEX 完整端到端（IANA #4590） | 国际项目仅 X-Wing #4588（X25519+ML-KEM） |
| 2 | 工程底座横跨 JS/WASM / C Addon / STM32 / Artix-7 FPGA | liboqs 侧重 C 库，缺少浏览器/硬件一体化 |
| 3 | 全流程 RFC3161 TSR 时间戳归档（94 份） | 绝大多数 PQC 项目仅有源码 |
| 4 | TLA+ 形式化验证 Path C-2 混合握手状态机 | 普通 demo 项目不涉及形式化 |
| 5 | 并行维护标准生产 + 自研密码研究（VWZ/LookingGlass） | 普通项目仅实现 NIST 标准算法 |
| 6 | 双轨降级架构：TLS PathA + 应用层 PathC-2 | 单一路径为主流 |

## 二、对标行业成熟 PQC 平台 — 现存缺失项

### P0 — 开源发布前建议补齐

| # | 缺失项 | 竞品现状 | FIBEMATE 现状 | 影响 |
|---|--------|----------|---------------|------|
| 1 | **标准跨平台测试矩阵** | liboqs CI 矩阵标注全部平台 | 测试分散在 TSR/脚本/文档 | 外部审计无法快速确认 |
| 2 | **持续模糊测试（Fuzzing）** | liboqs/oqs-provider/noble 均长期 OSS-Fuzz | 仅有 KAT/TVLA，无 fuzz | 报文解析高危攻击面未覆盖 |
| 3 | **内存安全审计** (ASAN/UBSAN) | C PQC 库标配 | 无 ASAN 记录 ⚠️ 但项目实为纯 JS，此项不适用 | — |
| 4 | **SPDX 许可证头部** | 每份源文件标注 SPDX | 仅根目录 LICENSE | 合规审查/企业引入会提出整改 |
| 5 | **漏洞追踪系统** | 漏洞编号/版本矩阵/公告模板 | 仅零散记录 | 安全事件响应不标准 |

### P1 — 中长期补齐

| # | 缺失项 | 影响 |
|---|--------|------|
| 6 | 移动端真机测试套件（Hermes 引擎） | RN 宣称无法验证 |
| 7 | PathA 完整客户端 Demo | 只有服务端，无客户端复现样例 |
| 8 | 标准化 Benchmark Docker 镜像 | 外部无法复现性能数据 |
| 9 | FPGA 约束文件 + testbench 公开 | Verilog 代码不可直接复现 |
| 10 | API 稳定度承诺 | Stable vs Experimental 无区分 |

### P2 — 长期生态

| # | 事项 |
|---|------|
| 11 | 漏洞赏金计划/安全联络通道 |
| 12 | 预编译二进制分发（WASM/Release） |
| 13 | 网页交互式 Demo |
| 14 | Python binding 示例 |

## 三、校正说明（2026-07-22 实际代码审查）

> ⚠️ **P0 第 3 项（ASAN/UBSAN）不适用于当前项目**
> 
> `packages/pqc-kem/` 下无任何 C/C++ 源文件。ML-KEM-768 为纯 JavaScript 实现，`package.json` 声明 "No deps, no WASM"。
> ASAN/UBSAN 仅在有 C native addon 时才需要。
> 
> *在 `packages/` 目录下确认无 `*.c`, `*.cc`, `*.cpp`, `*.h` 文件。*
