# FIBEMATE 当前状态：已验证的数字，与没做完的部分

> 2026-10-25 · 工程状态说明（形式化账本与依赖两项数字按 10-24 / 10-25 复核）

FIBEMATE 是一个后量子密码（PQC）的工程验证平台：ML-KEM / ML-DSA / SLH-DSA 与 SM2/SM3/SM4 的实现、跨语言互操作、CBOM 供应链物料清单，以及一条在 Isabelle/HOL 中推进的 VWZ 构造形式化线。

它不是产品发布，也不是融资贴。发这篇的原因很具体：主仓的 OpenSSF Scorecard 里 Code-Review 一项是 0（0/28 个有审批的变更集），这是单人维护结构的硬伤，只能靠外部评审补。下面把当前状态、已验证的数字、以及明确没做完的部分分开写清楚——凡是能复跑的都给出命令或入口。

### 已经有实体的部分

- `F_3329` 域表示。
- 燃料参数化的 Gauss–Jordan 消元：`mat_rank`、`dim_nullspace`、`mat_inv` 不再是未解释常量。燃料让递归是结构递归，不需要终止性证明；但"消元到达行最简形""rank 等于域上秩""逆是双侧逆"这些没有被声称。
- §3.1 的 LCG 作为状态机（`nat ⇒ nat × nat`，返回值与后继状态）；拒绝采样采样器证的是部分正确性：返回值非空时，长度、互异、范围成立。终止性只以概率 1 成立，本 session 没有测度论，因此不作声称。
- §3.3 的行加法矩阵生成器（`m*m` 轮，`i=j` 时两次抽取都消耗后跳过）、按规范顺序生成四个矩阵、以及按 §3.6 字段填充的 KeyGen 实体。
- `hash_target` 有实体了：池内的部分 Fisher–Yates 走位 + 指示向量（`fy_fuel` / `swap_at`），稠密性由走位长度保证，不靠假设。


### 四处被机器判定的陈述

| 义务 | 缺陷 | 状态 |
|---|---|---|
| T2_B3 | 按整数陈述可逆，实现每步模 3329 归约（域错配） | 改述到 F_q 后**已闭合** |
| T2_D4 | 对非方阵系统误用行零化度（口径错配） | 改用列零化度后**已闭合** |
| T2_B7 | 断言 ψ 每片秩为 2，但前提不排除零切片 | 补非零 2×2 子式前提后**已闭合**（2026-10-24） |
| T2_D5 | `Eval` 收不到 k / msg，却要求目标位依赖消息 | **机器反证**，待签名语义 |

T2_B7 的反例满足前提而秩为 0，记录在 `VWZ_Refutations.thy`。原因是陈述缺良构前提——这是陈述缺陷，不是证明失败。把反例留在仓里，比悄悄删掉更有用。

改述后它已经闭合：补上「存在非零 2×2 子式」这一前提，秩 ≤ 2 由「每片是两个外积之和、因而行落在二维 span 内」得到（`rows_in_span_psi_slice_of` + `mat_rank_le_two_of_rows_in_span`），秩 ≥ 2 由非零子式得到（`rank_ge_two_of_nonzero_minor`），两侧夹出 `mat_rank (psi_slice …) = 2`。这条路只证明这一族切片，**没有建立通用秩理论**。

这不仅是诚实，更是后续迭代的锚点：每一次改述都有机器证据可回溯，下一个人不必重新争一遍。


### 已知缺口

- **T2_D5 是唯一剩余缺陷**：`Eval` 是 `consts`，不接收 k / msg，而义务要求目标位依赖消息。这是规范本身的冲突，不是证明欠账；要修它得先决定 `Sign` 的签名语义，所以保留 `sorry` 与缺陷标签，等规范决策。
- 原计划的通用秩理论（行最简形、子式在初等行变换下的不变性、`mat_rank (A·B) ≤ n_cols A`）标记为 **superseded**：T2_B7 已用二维 span 的窄路线闭合，这几个引理不再是前置条件。
- T3 剩余 **2 条**：概率与安全层的建模，需要先把签名语义定下来。
- `digest`、`Eval`、`Sign`、`Verify`、`sample_below`、`nullspace`、`mat_solve` 仍是未解释常量，逐个标 `TODO(define)` 并注明所缺的规范内容。不写"忽略参数的占位定义"——那会让引理变成关于一个自造矩阵的陈述，比留着洞更糟。
- 该仓目前没有 CI，也没有独立的 CONTRIBUTING；构建与计数命令在 README 里。构建：`isabelle build -D aligned`；负向对照：`isabelle build -D neg` 必须失败。


## 三、当前缺口（按上手难度排序）

1. **T2_D5 的规范决策**：给 `Sign` / `Eval` 定语义（消息与目标位如何联结），才能决定这条义务是改述还是删除。
2. **T3 剩余 2 条**：签名语义（Sign 的输入输出与 pk 的联结）定下来之后才能谈目标独立性。
3. **ACVP 向量走公共 API**：`fml-dsa` 已透传 FIPS 204 的 context / extraEntropy，并有行为对照；但 75/75 的 KAT 只覆盖 KeyGen，sigGen / sigVer 的向量级覆盖还没有。
4. **RN 仓测试与 CI**：`fibemate-mobile` 的 `node:test` 模式已跑通，`fibemate-react-native` 的 test 脚本只有 jest，无测试文件时是否会静默通过尚未实测。
5. **CBOM 进 PR 门禁**，以及 npm / pip / 镜像层的 hash 固定。
6. **外部 code review**：Scorecard 的 Code-Review 0/28，每一个实质性评审都直接改变这个数字。


## 四、协作约定

- 提交必须 DCO sign-off；PR 落后 base 时用本地 rebase，不要用 GitHub 网页的 "Update branch"（它会生成不带 signoff 的 merge commit）。
- 不接受掩盖错误。能用证据推翻既有结论的 PR 会被优先处理；被推翻的陈述会保留在仓里（T2_B7 就是例子）。
- 声称与实现必须对齐：文档里写"已实现"，代码里就得有对应实体；写不出来就标 `TODO(define)`，不编造语义。
- 提交前请自证：给出命令、输出，以及必要的字节级检查（编码、BOM）。
