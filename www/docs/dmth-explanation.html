DMTH 模型说明

深度可乘性陷门硬度 — 对 LookingGlass 的安全模型修正

一句话：DMTH 不声称 LWE 被嵌套后变"更难解"。它声称的是——即使攻击者解开了 LWE，他们面对的不是明文，而是 d−1 层需要逆向工程的 Kronecker 嵌套结构。

1. DMH 原来的声称（已被修正）

DMH（Depth-Multiplicative Hardness）声称：多层 LWE 嵌套的难度随深度 d 指数增长——即 d=2 比 d=1 安全，d=3 比 d=2 更安全。

这个声称在 BKZ 结构分析下被证明不成立：攻击者收到的公钥是一个标准 LWE 实例（A, b = A·s + e），无论 d 是多少，BKZ 攻击的复杂度由 n 和 q 决定，与 d 无关。

2. DMTH 修正了什么

DMTH（Depth-Multiplicative Trapdoor Hardness）将 深度 的含义从"攻击难度"重新定义为"陷门结构复杂度"——不再声称 d 阻止攻击者求解 LWE，而是声称 d 阻止攻击者在求解 LWE 之后 恢复明文。

类比：LWE 是一把锁——攻击者可以找到钥匙（求解 LWE）。但 DMTH 是把物品放在锁后面的一叠嵌套文件夹中——即使有钥匙，你仍然需要逐层拆解嵌套的 Kronecker 结构（d−1 层），才能拿到里面的东西。

3. 为什么这个区分很重要

如果你声称你做了一个"更安全的锁"而实际上锁没变，那是虚假宣传。但如果你说"锁后面的箱子里还有 d−1 个嵌套箱，即使打开锁也得继续拆箱"——这是一个不同的、诚实的主张：

  • 不夸大已有的安全：LWE 的安全性由标准格归约复杂度确定
  • 诚实描述叠加的防御：Kronecker 嵌套是为攻击路径增加了一层需要逆向工程的混淆
  • 在假设被证伪后仍有价值：即使 Kronecker 嵌套被证实在多项式时间内可分解，"为什么可分解"的分析与"如何修复"的论文都代表有价值的研究

4. 当前状态

  • DMTH 的 数学定义 已闭合——深度参数 d 准确定义了 Kronecker 嵌套层数
  • BKZ 结构分析确认：公钥在攻击者眼中是标准 LWE 实例
  • χ² 独立性扫描通过：7 参数（n=8/16/32, σ=1/3/5），无显著层间相关性（Cohen's w ≤ 0.258）
  • 技术文档 v2 已生成（内部归档）
